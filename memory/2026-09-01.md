# 2026-09-01 — RAG-TDI (K2 Data Center)

## Tugas
Pak Bos minta sistem RAG untuk project tender "K2 Data Center", self-hosted di server TDI.
Flow: baca dokumen → chunk → simpan (vector) → retrieve → rerank → generate.
Persyaratan: hierarki penyimpanan per project (project satu beda dari project lain).
Sumber data: `T:\04 Bid Support\FY 2026\K2 Data Center`.

## Yang dikerjakan
- Survey data: 180 file di T: (173 PDF, 6 XLSX, 1 ZIP) ~640MB. ZIP drawing diekstrak → total 166 dokumen dibaca.
- Survey server: Windows, Xeon E-2336 (6c/12t), RAM 32GB, TANPA GPU, tanpa Docker/Python/Ollama.
- Install: Python 3.12, Ollama 0.33.2, model `nomic-embed-text` + `qwen2.5:7b`, Qdrant v1.19 (binary, bukan Docker).
- Bangun pipeline modular di `C:\Users\Administrator\.openclaw\workspace\rag-tdi`:
  - config.py, reader.py (PDF/XLSX/DOCX), chunker.py (recursive), embedder.py (Ollama batch),
    store.py (Qdrant), reranker.py (cross-encoder), generator.py (LLM), pipeline.py, cli.py.
- Hierarki per project = satu collection Qdrant per project + metadata `project` di tiap chunk.
- Index K2: 166 dokumen → 5.321 chunk → tersimpan (status green, 768 dim).
- Uji query end-to-end berhasil: jawaban grounded + sitasi sumber yang benar.

## Keputusan desain
- Vector DB: Qdrant (self-hosted binary, tanpa Docker Desktop karena berat & tanpa GPU).
- Embedding: Ollama nomic-embed-text (batch /api/embed).
- LLM: qwen2.5:7b (CPU inference, data privat aman).
- Rerank: cross-encoder ms-marco-MiniLM-L-6-v2.

## Pelajaran / gotcha
- qdrant-client v1.19: method `search` → `query_points`.
- Qdrant binary v1.19: arg `--storage` tidak valid; pakai config file `--config-path`.
- Embedding satu-per-satu via ollama python-lib sangat lambat; batch HTTP /api/embed ~12x lebih cepat.
- PDF tender banyak yang warning "Multiple definitions" (pdfminer) — di-suppress.
- Score cross-encoder logit mentah negatif → di-map ke sigmoid 0..1.
